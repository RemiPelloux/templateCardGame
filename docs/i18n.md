# Translations

The app speaks English and French. Every word a player reads goes through `t()`; the server
only sends codes. Adding a language is one line, then the translations the compiler asks for.

## How it works

`packages/i18n` is a small translator with no dependency: placeholders, plurals that follow
each language's rules, number and date formatting, and typed bundles.

Each feature keeps its text next to its code, in `i18n.ts`:

```ts
export const shop = defineBundle({
  en: { title: 'Shop', price: { one: '{count} coin', other: '{count} coins' } },
  fr: { title: 'Boutique', price: { one: '{count} pièce', other: '{count} pièces' } },
});
```

- English is the reference. Every other language must have exactly the same keys, or the code
  does not compile; `apps/web/tests/i18n.test.ts` also checks that placeholders match.
- `apps/web/src/i18n/messages.ts` gathers the bundles. Keys read `namespace.path` and are
  typed: `t('shop.price', { count: 3 })`; a typo is a compile error.
- A plural is an object with `other` and the forms the language needs (`one`, `few`…). With a
  count of zero, a `zero` form wins when present.
- `format.number`, `format.date`, `format.dateTime` and `format.relative` format for the
  reader's language.

## Where the text lives

| Text                                  | File                                        |
| ------------------------------------- | ------------------------------------------- |
| Shared words, navigation, core errors | `apps/web/src/i18n/common.ts`               |
| A feature's screens and errors        | `apps/web/src/features/<feature>/i18n.ts`   |
| The game: cards, log sentences, rules | `apps/web/src/game/i18n.ts`                 |
| An expansion                          | `apps/web/src/game/expansions/<id>/i18n.ts` |
| The generic table                     | `apps/web/src/table/i18n.ts`                |

The game log is stored as events with data, never as sentences, so each player reads a match
in their own language.

## Errors

The server answers `{ error: { code, message, params } }`. The client shows the first of:

1. `game.errors.<CODE>`;
2. `<namespace>.errors.<CODE>` in any other bundle, so a feature translates its own codes;
3. `common.errors.<CODE>`;
4. the server's English message;
5. `common.errors.UNKNOWN`.

`params` fill the placeholders: `INVALID_USERNAME` comes with `{ min, max }`.

## Choosing the language

On each visit the app uses the language remembered on this device (`localStorage`), else the
browser's preferred languages, else English.

Signing in applies the account's saved language and remembers it on the device, so a member
finds their language on every device. An account without one adopts the device's language at
sign-in. Members change it under _Account → Language_, which updates both.

## Adding a language

1. Add it to `LOCALES` in `packages/i18n/src/locales.ts`: `de: { label: 'Deutsch', intl: 'de-DE' }`.
2. Run `pnpm check`. TypeScript lists every bundle without a `de` entry.
3. In each, copy the `en` block to a `de` block and translate it. Add plural forms the
   language needs (`few`, `many`).
4. Run `pnpm test`: the translation tests check every key and placeholder.
