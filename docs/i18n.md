# Translations

The app ships in **English** and **French**. Every word a player reads goes through `t()`;
the server only sends codes.

## How it works

- `packages/i18n`: the translator (placeholders, plurals with the locale's rules, number and
  date formatting), the list of locales and typed bundles. No dependency.
- Each feature keeps its text next to its code in `i18n.ts`:

  ```ts
  export const shop = defineBundle({
    en: { title: 'Shop', price: { one: '{count} coin', other: '{count} coins' } },
    fr: { title: 'Boutique', price: { one: '{count} pièce', other: '{count} pièces' } },
  });
  ```

  English is the reference: the French entry must have exactly the same keys, or TypeScript
  refuses to compile. `apps/web/tests/i18n.test.ts` also checks keys and placeholders.

- `apps/web/src/i18n/messages.ts` gathers the bundles; keys read `namespace.path`, typed:
  `t('shop.price', { count: 3 })`. A typo is a compile error.
- **Errors**: the server answers `{ error: { code, message, params } }`. The client shows
  `game.errors.<CODE>`, else `common.errors.<CODE>`, else the server's English message.
- **Game text** (card names, log sentences, rules) is in `apps/web/src/game/i18n.ts`; the log
  stores events as data, so a match is described in each reader's own language.
- **Choosing the language**: the account's saved language, else the one picked on this device,
  else the browser's (`navigator.languages`), else English. Members change it under Account.

## Adding a language

1. Add it to `LOCALES` in `packages/i18n/src/locales.ts`: `de: { label: 'Deutsch', intl: 'de-DE' }`.
2. Run `pnpm check`. TypeScript lists every bundle that lacks a `de` entry.
3. In each of those files, copy the `en` block to a new `de` block and translate it.
4. `pnpm test` checks that every key and placeholder made it.

Plural forms follow `Intl.PluralRules`: add `few` / `many` where the language needs them
(Polish, Russian…).
